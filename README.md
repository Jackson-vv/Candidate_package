# Архитектура DWH

Решение построено по классической трехуровневой архитектуре.

# Raw слой

Содержит таблицы, максимально близкие к исходным CSV файлам:
- raw_sales_1c - продажи из 1С
- raw_plan - планы продаж
- raw_sku_links - связи старой и новой номенклатуры
- raw_stock_movements - движения товаров на складах

Загрузка выполняется через функцию read_csv_auto(), которая автоматически определяет типы колонок.

# Staging слой

Содержит подготовленные данные после валидации и трансформации.

stg_sales - продажи после очистки:
- Приведение типов (даты к DATE, числа к DECIMAL)
- Удаление дублей по doc_id (оставляется первая запись)
- Замена старой номенклатуры на актуальную через LEFT JOIN
- Сохранение отрицательных продаж (возвраты не удаляются)

stg_plan_raw - планы с приведенными типами данных

stg_plan_daily - план распределенный по дням:
- Генерация всех дней месяца для каждой комбинации связь-регион-товар
- Расчет дневного плана по формуле: месячный план * (вес дня / сумма весов недели)

stg_stock_movements - движения товаров с приведенными типами

# Mart слой

Содержит готовые для анализа таблицы.

mart_sales_plan_daily - основная витрина план/факт:
- FULL OUTER JOIN между продажами и планом
- Поля: дата, регион, цепочка, название цепочки, товарная группа, факт, план, разница, процент выполнения
- Если факта нет, но план есть - строка создается
- Если план не задан, но есть продажи - строка создается

mart_last_customer_operation - последняя операция каждого клиента 
mart_rolling_7d - скользящая сумма продаж за последние 7 дней
mart_mtd - накопление продаж с начала месяца
mart_stock_daily - остатки на складах по дням с расчетом стоимости
